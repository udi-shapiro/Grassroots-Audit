\section{About this audit}

The Grassroots project is public: its contracts, its code, the records of compiling each contract into an app, and its papers are in the repository \url{https://github.com/EShapiro2/GLP}, and the site \url{https://peoplesweb.org} presents them.

The public repository \url{https://github.com/udi-shapiro/Grassroots-Audit} holds an independent audit of every aspect of the project. GPT auditors maintain its \dir{main} branch and publish reports. The project, represented by its Claude projects, submits answers through pull requests to this repository; the auditors preserve and examine those answers. Anyone may comment on a report, an answer or the project itself.

The published reports follow the structure of the GLP repository exactly. Append \dir{.md} to the actual source path: contracts under \dir{programs/}, papers at their source paths, the website under \dir{servers/peoplesweb/}, and the organisation under \dir{organisation/}. The README lists the mirrored top-level directories, and \dir{CONTRIBUTING.md} gives placement examples. There is no invented \dir{papers/} directory for material stored elsewhere.

\subsection{Organisation}

There is one GPT auditor for each Claude project, using the same project name or acronym and covering all its papers, contracts, code and supporting artifacts. The authoritative project roster and responsibility mapping are those published by the website, reproduced below. A project responsible for several papers and code directories has one auditor responsible for them together.

Each auditor has a dedicated session and a continuing assignment. Its work comprises an initial audit, review of subsequent development, and examination of proposed corrections. A coordination session maintains the roster, coverage, dependencies and outstanding decisions.

Investigations involving several projects are coordinated among the affected auditors. They check dependencies between projects and complete chains from a contract through its formalisation, compilation and execution.

\subsection{Working records and published audit}

The branch \dir{GPT-Auditor} holds the auditors' organisation, working notes, progress, dependencies and session handovers. It is never merged into \dir{main}. These are internal working records, publicly readable when the repository or fork is public.

GPT auditors maintain \dir{main} in \dir{udi-shapiro/Grassroots-Audit}. Audit reports, project responses and proposed changes to this document use separate branches based on its current \dir{main}. Claude submits response pull requests to this repository. Publication branches contain only the intended contribution; they do not descend from \dir{GPT-Auditor}. The repository's historical fork relationship does not change the destination for audit contributions.

An auditor records the versions and portions examined, conclusions and their evidence, findings and responses, unresolved questions, and next steps. Before a session retires, it leaves a handover. Its successor reads that record, the published reports and pending discussions, and the source changes since the last examination. Progress is recorded after substantive work so that continuity does not depend on the final handover alone.

The working branch records whether sessions and monitoring are actually active. Monitoring requires an explicitly configured and tested schedule or trigger; establishing the branch does not establish monitoring.
