# Audit issues

Updated 25 November 2026. The 35 published reports contain **60 numbered findings**. **18 are resolved and 42 remain open.** Of the 42 open findings, 35 have project answers and 7 await a first answer. Verified resolutions include withdrawn claims. Each report retains its attributed answers and verification history.

All six original core findings now have answers, including vGLP's merged [PR #23](https://github.com/udi-shapiro/Grassroots-Audit/pull/23). The answer-based hold has therefore ended. Their revised proofs and code still require independent verification.

[GitHub Issues](https://github.com/udi-shapiro/Grassroots-Audit/issues) is enabled. Every published numbered finding has a linked ticket below. This index maps the tickets to the full reports and their stable finding identifiers. Anyone with a GitHub account can report a concern or contribute a pull request from a fork; see [CONTRIBUTING.md](CONTRIBUTING.md#contributions-from-anyone). A merged response records the answer; only the auditor's verification closes a finding.

## Shared known-red checks and remaining coverage

The [KNOWN_RED_CHECKS registry](test/run_all_tests.sh.md) is reported once, with its source version. It is not duplicated as a new finding for each application.

Remaining coverage is distinct from demonstrated faults. It includes currency boundary cases (invalid amounts, insufficient funds, dates and concurrent transactions), the newer handwritten bonds implementation, full store-to-install execution and physical-device coverage, and the remaining core proofs and implementation tests listed in the [coverage table](README.md#stage-2-bounded-core-sweep). Findings discovered in that work will receive their own stable report identifiers and be added here.

## Keeping this index current

When publishing a finding, response or verification, update its ticket and its row here alongside the report. Before creating a ticket, check for the same report path and finding number; retain that ticket across responses and corrections. Keep it open until independent verification is recorded, and close it as completed when the reported fault is verified corrected. A public concern or proposal is not automatically an accepted audit finding. Preserve attributed answers and earlier evidence; distinguish unanswered, answered, partly corrected, verification pending and verified corrected. Regenerate `sections/status-table.tex` with `python3 bin/status.py` when reports change; its unanswered count is different from the unresolved count in this index.
