# Compiling Grassroots Contracts into vGLP — mathematical review

27 November 2026 · Grassroots Review · Compiling GC revision (1), 26 pages · Calculus revision (17), 15 pages · OSPM full version, 82 pages.

**Verdict.** The revised paper correctly imports the core clause semantics and the grassroots-for-persons theorem from Calculus (17). Lemma 4.2 explains why a fixed ground act admits local votes. The deciding vote gives an atomic point for its state change. The main proof gap concerns the completeness half of Theorem 4.19. There are also reachable cases in which the two proposed abstraction maps fail to produce configurations of their stated targets. Theorem 7.1 ends at vGLP. Retiring OSPM as a mathematical reference requires a result for the last compilation and an explicit account of the old specifications still covered.

**What works in the transaction proof.** For a fixed act, its body literals, tests, and constraints on source and target factor over its participants. The ground head fixes an addition and deletion set at each. Lemma 4.2 leaves one global requirement: somebody changes. The changed bit on a yes vote and the initiator's own test supply precisely that requirement. A stationary participant in a guarded act can vote yes. The deciding Tally, or the successful unary Propose, then accounts for the participants' settled states in one abstract step. Later Commit and Outcome materialize those states locally.

**Two qualifications.** Definition 4.12 enlarges the raw Calculus equivalence on the implementing contract, grouping, for example, Request with Approve at an agent. The sentence following Lemma 4.13 establishes the grassroots property of the raw contract semantics. If this is also claimed for the implementing system with enlarged equivalence, give the transfer argument. Also, Calculus §3.2 gives each agent a time and place. Definitions 1.2 and 4.1 and Lemma A.2 model state-based tests and a machine state frozen by a yes vote. A clock or location read afresh during a lock needs a snapshot or an explicit input and revalidation rule. OSPM §5.4 qualified its environment-dependent results. Specify which interpretation is covered here. For negated tests, both papers' induced-transaction rule tests absence of an atom, while a positive test calls the test evaluator. If negative tests are legal, specify their evaluation in both papers.

## Open mathematical findings

Numbers continue the audit record for the predecessor paper. All five concern revision (1).

### 2. Standing requests need names and a population

Definitions 4.3, 4.5–4.6, 4.14, 4.18 and 6.1; Lemma A.7. Two restrictions are needed.

* **Representability.** Definition 4.3 allows every subset of the classes an agent guards. A single unary clause that can add mark(n) for any integer gives an agent countably many distinct classes. Their powerset is uncountable. Definition 4.5 represents each standing request by a term, but the language has only countably many finite terms. This problem occurs in §4, before §6 assumes decidability. Specify a family of named requests with a membership relation. For compilation provide its membership and enumeration procedures. OSPM 3.8 limited standing requests to decidable sets.
* **A reachable failure.** Let Alice guard the classes of a binary act with each possible partner. For example, its rule adds done(y) at x, reads eligible(y) at x and open at y, and is guarded by x. Let the identifier-free request name *all* denote all of Alice's partner classes. Over the singleton population consisting of Alice, the unary Stand is free to run initially after the requisite volition change. Its record contains *all* and a counter. It names no outsider syntactically. Indeed, as soon as Alice wills its standing class, Definition 4.14 already makes her will every class in its denotation. Definition 4.18 therefore includes the class for Alice and Bob, although Bob is outside this population and that class has no representative in its transaction set. VMAT Definition 24 and Lemma 25 exclude it from the target volitional state. The local premise eligible(y) makes the candidates finite at each state even for this wildcard.
* **Repair.** Define request denotations relative to the population, or explicitly intersect the projected classes with those of the source system over that population. Use the convention consistently for approval, willingness, freedom and fairness. In Lemma A.7 verify both guard membership and membership in the population's class set. If the latter restriction was implicit, this makes it precise.

### 3. Pairwise fairness does not establish class fairness in the completeness construction

Theorem 4.19 and Lemmas A.11–A.12, especially the last fairness argument in A.12. The constructed run must serve a Request of p for class U if it is enabled repeatedly and U never decides. The scheduling guarantee serves each fixed idle pair (p,a) that recurs infinitely often. Section 4 allows infinitely many acts in U.

Take the clause that adds done at p, with body p:tag(n), ¬p:done, q:gate, guarded by p. On a state containing both tag(i) and tag(j) and with the gate open, the two ground acts induce the identical machine transaction. Hence all these acts belong to one class U under Definition 1.6. Consider an abstract run in which p wills U, q's gate stays closed, and an independent unary clause replaces tag(n) by tag(s(n)) at p. Start with just tag(0). A guarded initializer can supply that tag and a separate guarded clause can open the gate on other runs. The advancing transactions can be taken as soon as enabled. U is never enabled in this source run, so its strong fairness places no obligation to take U.

At every successive quiescent stage p is locally ready for an act of U and its Request is enabled. Its only witness there is the current n. No particular idle pair recurs infinitely. A schedule serving none of these pairs satisfies the stated recurring-pair condition but misses the Request class. The inference from infinitely many eligible stages to a recurring pair fails. A bounded check of 2, 32 and 256 distinct tags reproduces the finite prefixes. The unbounded argument follows from the successor construction.

**Repair.** Schedule the recurrent obligation (p,U) and choose a currently eligible witness when it is served, retaining fair service of recurring individual Propose obligations. Prove existence of a schedule serving both countable families. Alternatively, assume finitely many acts per class in the completeness half of Theorem 4.19. Definition 6.1(1) makes that assumption later. This gap concerns lifting strongly fair source runs. The forward correctness claim used by 7.1 does not depend on this completeness argument.

### 4. The platform mapping admits self-acquaintance

Definitions 1.3, 3.1 and 6.2–6.3; Theorem 6.4. In a singleton population let p establish itself and answer its next request question with acquaint(p). The interactive type allows acquaint(q) for an agent q. As soon as the goal reads the answer, Definition 6.3 puts the class of Acquaint(p,p) in its mapped volitional state. Acquaint has two distinct role variables, with no permission to identify them. Consequently there is no such ground act or class. The failure precedes any network operation. If a self-hello were sent, Definition 6.2 would also infer knows(p) from the same send in both positions.

**Repair.** Ignore a self-addressed request before forming an abstract will. Require distinct peers in the hello handlers and both mappings. Clarify that the initial hello may go to a fresh peer. The restriction on sending to recorded recipients on p. 11 is appropriate for the protocol messages in Definition 4.5. Applying it to the initial hello would prevent the first contact used in Proposition 6.5. Check both a singleton and two strangers.

### 5. State the domains of the abstraction maps and the times at which the lock invariants hold

Definitions 4.5, 4.12, 4.18 and 6.2; Lemmas A.1, A.2 and A.7. An implementation map in the cited framework is a function on the concrete configuration space. Definition 4.12 constrains only the application part of a local state. A state containing two distinct lock atoms is therefore admissible as a configuration but has no unique lock for Definition 4.18 to read. An arbitrary vmaGLP resolvent likewise need not contain the unique compiled agent state assumed by Definition 6.2. Invariants proved from the initial configuration establish the map on reachable configurations. Restrict the systems to their reachable parts, or specify the valid representations and extend the maps on the complement. Findings 2 and 4 still require repairs on reachable configurations.

Two temporal statements also need tightening. Lemma A.1 says an attempt closes once at its initiator in a safe run. A finite safe prefix can end just after proposal. The safety fact is closure *at most once* and the outcome's unique provenance. Eventual closure is Proposition 4.15 under liveness and responsiveness. Lemma A.2 says that once an attempt is decided its effect changes some participant's machine state. After a committed unary addition of a flag, adding it again changes nothing. The invariant needed is that the effect changes at least one participant's locked pre-state **at decision**.

### 6. The replacement needs a result for the revised vGLP down to GLP with persons

Section 5 and Theorem 7.1; OSPM §§5–6. OSPM 6.11 composes three maps. Compiling GC 7.1 composes two. The final sentence refers to a vGLP paper in preparation without giving a theorem, a version, the third map or its fairness hypotheses. OSPM 6.10 cannot simply be applied to the new target. Its map reconstructs held variables, Ask, Answer and readers' substitutions. Here Answer selects a typed ground term and reduces a goal in one transaction. A reader-free question persists until reduced. These differences affect safety, cancellation and completeness.

**Repair.** Reference an identifiable theorem for the system of Definition 5.6, with the GLP-with-persons mapping, its treatment of stale questions and widget assumptions. Compose that map with the two in 7.1, pulling properness and responsiveness back through it. Give a separate proof or citation for grassrootsness at the GLP-with-persons endpoint. Correct implementation alone does not imply that property. The division between manuscripts is sound if each part of the old result has an identifiable new statement and proof.

## A concrete boundary for compiler eligibility

A finite, syntactically grassroots Calculus contract need not meet the opener hypothesis. Give it Establish and Acquaint and an unguarded act with holders a, b, c. Its positive body is a:edge(b), b:edge(c). Its effects add a:first, b:middle, c:last, each required absent at its holder. Every participant changes and the body graph is the connected path a–b–c. No holder's positive body binds all three variables. The example remains valid if one adds a guarded pairwise clause creating edges, so such a path can be reached. Lemma 4.2 applies, but §4 supplies no opener. Finding 3 independently shows that finitely many clauses need not give finitely many acts per class.

There is also a structural limit on direct recovery. Let k be the maximum number of holder variables in any clause of a finite source contract. By Definition 1.3, each receives one agent and the participants are the holders of the ground literals. Every one-step act therefore has at most k participants. The elementwise set convention expands arguments at a holder and does not bind a varying number of holders. OSPM §5.4 admits a listed guarding role whose extent comes from a participant's state. Across finite populations that extent can exceed every fixed k. A clause-for-clause translation into one finite core contract cannot preserve those participant and guard sets for all populations. A bounded extent, a formal participant-expansion rule, or a multi-step refinement with a proof would change this conclusion.

A second example separates local checking from class preservation. OSPM can put equality of two participants' stored counters in the joint condition on their readings and give the operation one class regardless of the equal value. One natural Calculus encoding uses a ground n in both positive body literals. If a semantic constraint permits only one current counter per agent, the instances for i and j, i ≠ j, never induce the same machine transaction. In a contract with just this operation, Definition 1.6 therefore puts them in different classes. The encoding recovers the machine effects, but a person willing the single old class now has several different wills to express. An additional correspondence on classes or request denotations is necessary to justify this encoding.

For the OSPM migration, use the old act in which a ward's state supplies its current guardians while the guardians consent. Exhibit the Calculus clauses, grounded participants and guards, how the initiator obtains the full instance, and whether the person's request denotes the same alternatives and liveness class. A shared value can sometimes be supplied as a ground parameter and checked at both roles, but doing so can split a single old request into many classes. Show class preservation wherever that encoding is used. List the procedures the compiler is given for Definition 6.1, or show how it synthesizes them for its input syntax. Existence of an enumerator for an individual contract does not supply its code to a uniform compiler.

**Disposition.** Keep the locality and decision proofs. Fix the population and peer boundaries, repair the class-fair completeness argument, and state the representation invariant. Then a versioned companion theorem and a migration statement would establish exactly which OSPM results the replacement recovers.
